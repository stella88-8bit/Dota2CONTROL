# Проверка задержки

Запуск приложения: `.venv/bin/python main.py` из папки проекта.
После обновления конфига GSI нужно полностью перезапустить Dota 2.

Клавиши отправляет отдельный поток `spell-control`. Он просыпается при готовом
результате Whisper, пакете GSI или наступлении срока следующего нажатия.
Окно, печать журнала и Vosk работают отдельно. Пока ввод включён, активность
macOS предотвращает App Nap; при выключении управления она завершается.

Голосовые прокасты используют `PredictiveComboRunner`: после Invoke прогнозируется
сдвиг ячеек (новое заклинание в D, прежнее D в F), а применение отправляется через
65 мс. Перед следующим заклинанием выдерживается 75 мс для завершения каста.
Ожидания отдельного пакета GSI после каждого Invoke или применения нет.

Из установленного `scripts/npc/heroes/npc_dota_hero_invoker.txt` получены базовая
перезарядка Invoke 7 с, снижение 0,3 с за каждый уровень сфер и время каста 0,05 с.
Уровни берутся из GSI. При 7/7/7 расчётная перезарядка Invoke составляет 0,7 с.
При неизвестных уровнях используется 7 с, пока новый GSI не подтвердит готовность
Invoke. Пауза между клавишами — 12 мс; фактический API macOS может работать дольше.

GSI проверяется параллельно. Запоздавший пакет не откатывает прогноз немедленно:
коррекция ячеек требует двух согласованных пакетов после 1,25 с ожидания.
Если последний Invoke не прошёл, его подготовка повторяется. Если оставшееся
в ячейке заклинание не применилось, два свежих пакета с нулевой перезарядкой
позволяют повторить его применение. Исправления ограничены двумя попытками.
Вытесненные из ячеек заклинания проверить или автоматически повторить достоверно
невозможно; они перечисляются как не подтверждённые, а не успешные.

Cold Snap сохраняет прежнее поведение: повторяется раз в 60 мс до подтверждения
применения, затем прокаст продолжается. Это единственный целевой шаг с обязательным
подтверждением: так последовательность не теряет Cold Snap до наведения на врага.
Потеря свежего GSI более чем на 2 с приостанавливает нажатия. «Стоп» отменяет
последовательность. Одиночные голосовые заклинания сохраняют исполнитель с
подтверждением ячеек до применения.

## Что означают измерения

- `VOICE timing`: обработка речи и оценка времени после её окончания.
- `очередь команды`: от готового результата Whisper до начала исполнения.
- `команда Invoke`: отправка R; в быстром прокасте подтверждения ячейки не ждём.
- `команда применения` → `GSI показывает перезарядку`: обработка применения игрой
  и доставка подтверждения. Это не измерение попадания в цель.
- `после предыдущей команды`: интервал между первыми отправками применения двух
  заклинаний; повторные попытки Cold Snap показаны отдельно.
- `Команды прокаста отправлены за` / `Отправка прокаста`: от результата Whisper
  до последней команды применения. Это не подтверждение попадания или всех кастов.
- `проверка завершена через`: время до итоговой проверки GSI; после отправки
  проверка может продолжаться до 3 с (продлевается после корректирующего применения).
- `Не подтверждены GSI`: заклинания, которые не удалось проверить по перезарядке.
- `GSI: интервал пакетов`: частота реально полученных обновлений, включая heartbeat.
- `Отправка … заняла`: выводится, если вызов клавиатурного API занял более 50 мс.

Метки времени формируются исполнителем. Поздняя печать строки интерфейсом
не добавляет времени в измерения и не задерживает клавиши.

## Локальный стенд

```sh
.venv/bin/python benchmark_latency.py --repeats 3 --gsi-ms 1000 --output outputs/predictive-combos-1s-gsi.json
.venv/bin/python -m unittest discover -s tests -q
```

Стенд использует настоящий исполнитель и HTTP-сервер, имитируя клавиатурный API
и ответы игры. Он не использует микрофон, не нажимает клавиши и не управляет Dota.
Во время прокастов очередь интерфейса и журнала намеренно не читается.
Параметры `--key-ms` (по умолчанию 16) и `--gsi-ms` (30) задают задержки имитатора.
Пакеты GSI задерживаются независимо от выполнения клавиш. Имитатор учитывает
уровни сфер 7/7/7 и перезарядку Invoke 0,7 с. `dispatch_ms` измеряет отправку
команд, `total_ms` включает итоговую проверку GSI.
Порядок применения и Alacrity на себя проверяются для каждой последовательности.

Результат стенда нельзя считать измерением задержки в Dota. Игровое время
подтверждается журналом из тренировки; перезарядка Invoke, доступность способностей,
наведение на цель и доставка GSI ограничивают фактическую скорость.
